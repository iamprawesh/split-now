# SplitWise App — Expense Sharing

Expense sharing app — split bills with friends, track who owes whom, and settle up with minimal transactions.

---

## Stack

| Layer | Technology |
|---|---|
| **Mobile** | Flutter (Riverpod StateNotifier, Material 3) |
| **Auth** | Firebase Auth (Google, Apple) |
| **Push** | Firebase Cloud Messaging via Admin SDK |
| **Backend** | Node.js + Express |
| **Cloud DB** | MongoDB Atlas (Mongoose ODM) |
| **Local DB** | SQLite via `sqflite` (offline cache scaffold) |
| **HTTP** | Dio with JWT interceptor |
| **API Docs** | Swagger/OpenAPI at `/api-docs` |

## Backend

### Entry Point (`server.js`)

1. Env loaded via `dotenv`
2. `helmet` (security headers), `cors`, `express.json`, `morgan('dev')`
3. Swagger auto-docs at `/api-docs`
4. Routes mounted:
   - `/api/auth` → `routes/auth.js`
   - `/api/groups` → `routes/groups.js`
   - `/api/groups/:id/expenses` → `routes/expenses.js` (uses `mergeParams`)
   - `/api/groups/:id/settlements` → `routes/settlements.js` (uses `mergeParams`)
   - `/api/notifications` → `routes/notifications.js`
5. Health check at `GET /api/health`
6. Firebase Admin intialized, then MongoDB connected, then server starts

### Auth Middleware (`middleware/auth.js`)

Two middleware functions:

- **`verifyToken`** — Extracts `Bearer <jwt>` from `Authorization` header, verifies with `jsonwebtoken`, sets `req.user` with decoded payload (`{ id, firebaseUid, name, email }`). Used on all protected routes.

- **`firebaseAuth`** — Verifies Firebase ID token via Admin SDK `verifyIdToken()`. If the Firebase UID doesn't exist in MongoDB, creates a new `User` document (upsert by decoding Google profile: name, email, picture). Sets `req.firebaseUser`. Used only on the `/auth/firebase` login endpoint.

### Services

#### Balance Service (`balanceService.js`)

**`calculateBalances(groupId)`**
1. Fetch all expenses + settlements for the group
2. For each expense: payer gets +amount, each split user gets -split.amount
3. For each settlement: `from` gets +amount, `to` gets -amount (settlements reverse the debt)
4. Returns `{ userId: netBalance }` map

**`simplifyDebts(balanceMap)`**
1. Split into creditors (balance > 0.01) and debtors (balance < -0.01)
2. Sort both descending by absolute amount
3. Greedy match: largest debtor pays largest creditor, min of the two amounts
4. Returns `[{ from, to, amount }]` — minimum number of transactions

**`calculateSplitAmounts(amount, splitType, splits, members)`**
| Type | Input | Formula |
|---|---|---|
| `equal` | (none — uses all active members) | `amount / N` per person |
| `parts` | Each person's `value` (integer parts) | `(value / sum(values)) × amount` |
| `percentage` | Each person's `value` (%) | `(value / 100) × amount` |
| `custom` | Each person's `amount` | Direct `amount` (must total to expense amount) |

Rounding remainder is always added to the last split to ensure total matches.

#### Notification Service (`notificationService.js`)

- **`sendPushNotification(userId, title, body)`** — Iterates user's `fcmTokens[]`, sends via Firebase Admin SDK. Invalid tokens (unregistered, invalid) are cleaned from the array and the user is saved.
- **`sendGroupNotification(group, excludeUserId, title, body)`** — Iterates active members (excluded the triggering user) and sends push to each.

## Expense Split Calculation (`balanceService.js`)

| Type | Input | Formula | Validation |
|---|---|---|---|
| **Equal** | (none) | `amount / N` per person | Uses all active members |
| **By parts** | Each person's `value` (integer) | `(value / sum(values)) × amount` | `totalParts > 0` |
| **By percentage** | Each person's `value` (%) | `(value / 100) × amount` | `sum(values) === 100` |
| **Custom** | Each person's `amount` | Direct value used as amount | `sum(amounts) === total` |

**Rounding**: Remainder from floating-point rounding is added to the last split's amount.

---

## Balance Algorithm (`balanceService.js`)

1. **Per-person net**: `sum(paid) - sum(owed from splits)`
2. **Apply settlements**: `from` gets +amount, `to` gets -amount (reverses the debt)
3. **Simplify debts**: Greedy algorithm — sort creditors and debtors by amount descending, match largest debtor to largest creditor, create minimum transactions
4. **Output**: `[{ from, to, amount }]` suggested payments

## Key Design Decisions

1. **JWT (not Firebase session)** for API calls — backend issues its own JWT so auth is decoupled from Firebase per-request verification
2. **Embedded arrays** in MongoDB — `members[]` in Group, `splits[]` in Expense — avoids joins, single query for reads
3. **Firebase Admin SDK** for push — sends FCM server-side, auto-cleans invalid registration tokens
4. **Material 3** with custom theme — consistent purple/green/red color scheme across all screens
5. **Soft-delete** for group members — `leftAt` timestamp set instead of deleting, allowing rejoin tracking
6. **Riverpod** over Provider — compile-safe, testable state management with `StateNotifier` for complex state

## Known Issues / Gaps

1. **`database_service.dart:73`** — `getCachedGroups()` casts `r['data']` as `Map<String, dynamic>` but data is stored as a string (via `.toString()`). Will crash at runtime.
2. **Offline queue not wired** — `pending_actions` and cached data are never used in the provider layer. The write/cache/read/flush cycle is scaffolded but not connected.
3. **`cached_expenses` dead code** — table is created in SQLite but never written to or read from any provider.
4. **`validators/` empty** — no `express-validator` chains. All validation is inline in controllers.
5. **`expenseController.js:52`** — `require('../models/User')` called inline inside `createExpense`; should be imported at the top of the file.
6. **`main.dart:20`** — `Firebase.initializeApp()` without `DefaultFirebaseOptions`. Works on Android/iOS (native config files) but will fail on web.
7. **`widgets/` directory empty** — no reusable widgets extracted. Group card, member tile, expense item all defined inline in screens.
8. **No tests** — no automated tests in either backend or Flutter app.

## Codebase Analysis

### Backend Architecture

```
server.js
  ├── helmet, cors, express.json, morgan (middleware stack)
  ├── Swagger /api-docs
  └── Routes
       ├── /api/auth          → authController.js
       ├── /api/groups         → groupController.js
       ├── /api/groups/:id/expenses  → expenseController.js  (mergeParams)
       ├── /api/groups/:id/settlements → settlementController.js  (mergeParams)
       └── /api/notifications  → notificationController.js
```

**Auth flow**: Firebase ID token → backend verifies via Admin SDK → upserts User doc → returns JWT. Subsequent requests use `Bearer <jwt>` verified via `jsonwebtoken`. This decouples auth from Firebase per-request verification.

**5 Mongoose models**: User (flat, no password), Group (embedded members[] + invite subdocs), Expense (embedded splits[]), Settlement (simple from→to→amount), Notification (5 type enums + refId). Embedded arrays avoid joins for reads.

**Balance engine** (`balanceService.js`): Three functions — `calculateBalances()` (sums paid minus owed + settlement adjustments), `simplifyDebts()` (greedy matching largest debtor to largest creditor for minimal transactions), `calculateSplitAmounts()` (handles equal, parts, percentage, custom with rounding remainder added to last split).

### Flutter Architecture

```
main.dart (Firebase init + ProviderScope + Material 3)
  └── SplashScreen (animated logo, waits for auth check)
       ├── AuthScreen (Google + Apple sign-in)
       └── DashboardScreen (bottom nav)
            ├── HomeScreen (group list + FABs)
            └── ActivityScreen (notification feed)
```

**5 providers** (Riverpod StateNotifierProvider with copy-with state):
- `AuthNotifier` — checkAuth, Google/Apple signInOut, FCM token registration
- `GroupNotifier` — CRUD, invite/join, optimistic UI (shows group instantly, rolls back on failure)
- `ExpenseNotifier` — CRUD, balances, settlements, optimistic UI
- `NotificationNotifier` — list, unread count, mark read
- `SettingsNotifier` — theme mode (light/dark/system) + currency (21 currencies), persisted to FlutterSecureStorage

**13 screens**, key design patterns: shimmer loading skeletons, custom pull-to-refresh wrapper, loading overlays, `_PulseDot` and `_ThreeDotLoader` animations.

**Optimistic updates**: CreateGroup and CreateExpense immediately show in UI before API response, roll back to previous state on failure.

**Offline scaffolding**: SQLite with 3 tables (cached_groups, cached_expenses, pending_actions) — schema and methods exist but are **not wired** into provider layer. Known bug: `getCachedGroups()` casts data as `Map` but stores as string → runtime crash.

## How to Run

### Backend
```bash
cd backend
cp .env.example .env
# Fill in: MONGODB_URI, JWT_SECRET, FIREBASE_PROJECT_ID,
#          FIREBASE_CLIENT_EMAIL, FIREBASE_PRIVATE_KEY
npm install
npm start
# API docs at http://localhost:3000/api-docs
```

### Flutter
```bash
cd flutter_app
# Place google-services.json in android/app/
# Place GoogleService-Info.plist in ios/Runner/
# Add SHA-1 fingerprint to Firebase Console
flutter run
```

### Firebase Setup
1. Firebase project: `split-now-4d077` (already configured in `firebase_options.dart`)
2. Enable Authentication → Google & Apple sign-in
3. Enable Cloud Messaging
4. Generate Firebase Admin SDK private key → set in `.env`

### MongoDB Atlas
1. Create free cluster at mongodb.com/atlas
2. Create database user, whitelist IP
3. Set connection string as `MONGODB_URI` in `.env`
